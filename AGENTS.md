# Project: language courses for school students

A static Next.js site with foreign-language courses for Polish school students (grade 7 = A1,
grade 8 = A2). Explanations, instructions and the UI are in **Polish**. The target languages
are German, Spanish, Italian, French, Portuguese, Catalan and Galician. There are no accounts
and no backend: lessons are TypeScript data, every page is pre-rendered
(`generateStaticParams`), and learner progress is kept in `localStorage`.

## Commands

```bash
npm run dev            # dev server (the owner usually runs it on port 3200: npm run dev -- -p 3200)
npx tsc --noEmit       # typecheck; this is the main check for lesson content, since lessons are typed data
npm run lint
npm run build
scripts/tts/generate.sh <ttsLang>   # regenerate lesson audio after content changes (see below)
```

## URL structure

`/<from>/<lang>/<grade>/<lesson>`, e.g. `/polish/german/grade-7/hallo-wie-heisst-du`.
`from` is the learner's own language. Only `polish` exists today, but the content model is
ready for more source languages (`src/content/index.ts`).

## Layout

| Path | Contents |
| --- | --- |
| `src/app/` | Routes: `[from]` (course picker), `[from]/[lang]` (course overview), `[from]/[lang]/[grade]/[lesson]` (lesson page). |
| `src/content/types.ts` | Content model: `Course`, `Grade`, `ChapterOutline`, `Lesson`, `Block`, `Exercise`. Read this first. |
| `src/content/index.ts` | Source-language registry and lookups (`getCourse`, `getLesson`, static params). |
| `src/content/polish/courses.ts` | Every course: slug, `ttsLang`, names, colours, grades → chapters → lesson outline (slug + title). |
| `src/content/polish/index.ts` | Imports each lesson and registers it under `"<course>/<grade>/<lesson-slug>"`. |
| `src/content/polish/<language>/<slug>.ts` | One lesson per file: `export const lesson: Lesson = { … }`. |
| `src/components/LessonBody.tsx` | Renders a lesson's blocks; voice warning and voice credits. |
| `src/components/blocks/`, `src/components/exercises/` | Block renderers (dialogue, vocab, reading…) and exercise types (choice/listen, fill, order, write). |
| `src/lib/speech.tsx` | Read-aloud: plays pre-generated MP3s and falls back to the browser's speech synthesis. |
| `src/lib/tts-audio.ts` | Shared by the site and the audio generator: phrase hashing, and the list of phrases a lesson reads aloud. |
| `src/lib/answers.ts` | Answer checking (forgives case, punctuation, and missing accents or umlauts → "almost"). |
| `src/lib/progress.ts` | Per-lesson exercise scores and self-check state in `localStorage`. |
| `scripts/tts/` | Audio generation (Piper, plus Proxecto Nós for Galician) in Docker. See `scripts/tts/README.md`. |
| `public/audio/<ttsLang>/` | Generated MP3s + `manifest.json`. Generated by the scripts; never edit by hand. |
| `references/` | Source material for course content (e.g. `references/catalan/`, with its own README). |

## Course content

- **Structure:** each grade has 8 chapters. A chapter has 3 lessons plus a review lesson
  (German "Wiederholung – Kapitel N", Spanish/Galician "Repaso – Unidad/Unidade N",
  Italian "Ripasso", French "Révision", Portuguese "Revisão"…), so 32 lessons per grade.
  The outline in `courses.ts` and the lesson files must agree.
- **Adding a lesson:**
  1. Create `src/content/polish/<language>/<slug>.ts`. The slug is the kebab-case target-language title, without diacritics.
  2. Add it to the chapter's `lessons` in `courses.ts`.
  3. Import and register it in `src/content/polish/index.ts`.
  4. Run `npx tsc --noEmit`.
  5. Regenerate audio for that language.
- **A lesson** is a list of blocks: `goals`, `dialogue`, `vocab`, `grammar`, `pronunciation`,
  `reading`, `culture`, `exercise`, `selfcheck`. Every target-language phrase has a Polish
  translation (`pl`). Polish text supports `**bold**`. Dialogue and reading titles are in the
  target language, read aloud, and need a Polish `titlePl` shown underneath.
- **Dialogues:**
  - `cast` gives each speaker's gender (`"f"`/`"m"`). It picks the voice, so keep it correct.
  - Recurring characters stay consistent within a course, so grep earlier lessons for their facts before writing.
  - Character names must be easy to pronounce in both languages: no Polish-only names or letters
    (ą, ł, ś…) in target-language text, because the voices misread them. The Polish protagonist
    is Laura (Italian), Julia (German) or Carla (other courses); her brother is Jan (German) or
    Daniel. In target-language text use the target language's form of Polish places (Krakau,
    Cracovia, Gdansk…). Polish hints in exercises go in `hint`, never inside the sentence that is
    read aloud.
  - Names are declined in Polish text (Laura → Laury, Laurze, Laurę, Laurą, Lauro).
- **Exercises:**
  - Each needs a unique `id` within the lesson (progress is stored per id).
  - `fill` accepts several `answers`; the first one is the one read aloud.
  - `choice` with `speakOptions` reads its options aloud, and `listen` reads `audio`.
- **Working style the owner prefers:** write lessons one at a time, read only the context
  you need (one recent lesson in the same language for format), then typecheck, register
  and report. Don't fan out to parallel agents for content unless asked.
- Catalan content follows the IEC norm, checked against `references/catalan/`
  (`node references/catalan/compare.mjs` lists reference items not covered yet).

## Audio (read-aloud)

- **Generation:** every phrase a lesson can read aloud is pre-generated per language
  (`scripts/tts/voices.json` maps each course to its voices).
- **Playback:** `speech.tsx` looks up `public/audio/<ttsLang>/manifest.json`, plays
  `<hash>.mp3` (the hash covers the voice id and the normalised text), and falls back to
  browser speech for anything missing.
- **After editing lesson text,** run `scripts/tts/generate.sh <ttsLang>`. Only new or changed
  phrases are synthesised, and unused files are removed. Until then, edited phrases use the
  browser voice.
- **New read-aloud content:** if a component starts reading something new, add it to
  `collectSpokenPhrases` in `src/lib/tts-audio.ts`, otherwise it never gets a recording.
- **Voice credits:** every voice is credited at the bottom of the lesson (`VOICE_SOURCES` in
  `LessonBody.tsx`: voice, dataset and licence). Several licences (CC BY, CC BY-SA, Apache)
  require it, so when you change a voice in `voices.json`, update its entry there too.
- **Testing a single phrase:** `scripts/tts/say.sh <ttsLang> <n|m|f> "text"`.
- **Not in git:** `.tts-cache/` holds downloaded models, job files and test output, and is gitignored.

## Conventions

- Tailwind CSS v4, no component library. Each course has its own accent colours (`accent`,
  `accentSoft`, `accentInk` in `courses.ts`).
- Client state uses small module-level stores with `useSyncExternalStore` (voices, rate,
  progress, audio manifests), not context-heavy state or extra libraries.
- Keep `src/lib/tts-audio.ts` dependency-free with relative imports, because Node runs it directly
  (`--experimental-strip-types`). `tsconfig.json` allows `.ts` import extensions for this reason.
- Commits: never add Claude/AI co-author trailers or "Generated with" lines.
